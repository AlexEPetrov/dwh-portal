# Simulation Analysis

Этот документ описывает экраны **Статистика**, **Распределение**, **Помесячно**, **Liquidity-at-Risk** и **Raw data** на странице `/valuations/simulation/analysis`.

Описание верхних фильтров вынесено в отдельную справку: [Верхние фильтры анализа](help:valuation-analysis-filters).

## Экспорт в Excel

Кнопка **Экспорт в Excel** формирует книгу сразу со всеми представлениями, независимо от
открытой вкладки: `Filter`, `Статистика`, `Распределение`, `Помесячно`,
`Liquidity at risk` и один или несколько листов `Raw data N`. Графики сохраняются как
изображения Plotly. При очень большом объёме raw data используйте **Download raw data**:
Excel-выгрузка имеет серверный предел, а CSV в ZIP предназначен для больших наборов.

## Общий смысл страницы

Страница показывает уже рассчитанные результаты Monte Carlo simulation. Пользователь выбирает источник данных и фильтры наверху, нажимает **Загрузить**, после чего переключается между представлениями одной и той же выбранной области анализа.

Важно: frontend не пересчитывает статистику сам. Он показывает значения, подготовленные backend для текущих фильтров, `observation_date`, периода и выбранной целевой величины.

## Открытие страницы и ссылка на текущее представление

Если страница открыта без query-параметров, frontend ищет самую новую доступную `observation_date`, для которой существует сохранённый баланс, выбирает наиболее новую запись metadata на этой дате, устанавливает режим **По балансу** и scenario `default`, затем автоматически загружает результат один раз. Период в balance mode определяется конфигурацией сохранённого дерева на backend и не передаётся в URL как `valuationYear`.

Полная ссылка считается авторитетной и восстанавливает источник, дату, valuation type, scenario, дерево, вкладку, вид графика и, для режима **По симуляциям**, период, target и повторяемые scope filters. Пример balance-ссылки:

```text
/valuations/simulation/analysis?mode=balance&observationDate=2026-07-31&valuationType=eod&balanceTreeSlug=main&scenario=default&subscreen=distribution&chartType=density
```

Перед загрузкой balance deep link проверяется по сохранённой metadata для сочетания `observationDate` + `valuationType` + `balanceTreeSlug`. Metadata может содержать любой `valuation_year`: год не является частью URL-контракта, но frontend использует найденное значение внутри request state, чтобы передать обязательные валидные границы соответствующего календарного года. Некорректная, неполная или недоступная ссылка показывает явную ошибку и не заменяется молча последним балансом.

После изменения элементов управления query string заменяется текущим полным состоянием без добавления лишней записи history. Поэтому адрес можно копировать как ссылку на текущее представление, а Back/Forward восстанавливают и автоматически загружают состояние соответствующей ссылки.

| Вкладка | Что показывает | Когда использовать |
|---|---|---|
| Статистика | Табличные агрегаты по всем sample values | Быстро оценить среднее, хвосты, разброс и downside risk |
| Распределение | График распределения выбранной величины | Понять форму риска: симметрия, хвосты, несколько областей плотности |
| Помесячно | Распределение чистого потока каждого месяца | Найти месяцы с наиболее волатильными притоками или оттоками |
| Liquidity-at-Risk | Распределение накопленной денежной позиции по месяцам | Найти потенциальный кассовый разрыв и размер liquidity reserve |
| Raw data | Исходные sample values текущей combined-выборки | Проверить числа, выгрузить данные, диагностировать выборку |

## Статистика

Вкладка **Статистика** агрегирует все значения выбранной величины в одну таблицу метрик. Один sample обычно соответствует одному Monte Carlo сценарию после применения фильтров и агрегации.

Основные метрики:

- **COUNT** — количество sample values в выборке;
- **AVG** — среднее значение;
- **MED** — медиана, то есть центральный сценарий;
- **MIN** и **MAX** — крайние значения выборки;
- **STD** — стандартное отклонение, мера разброса;
- **P05** и **P95** — нижний и верхний перцентили;
- **CVaR95** — среднее значение в неблагоприятном хвосте распределения.

Бизнес-интерпретация:

- **AVG** полезен как expected value, но может быть искажен хвостами;
- **MED** показывает типичный сценарий;
- **P05** и **CVaR95** помогают оценить downside risk;
- большой разрыв между **AVG** и **MED** означает асимметрию распределения;
- высокий **STD** означает, что результат сильно зависит от сценариев рынка или контуров фильтрации.

Эту вкладку удобно использовать как первый контроль: есть ли данные, сколько sample попало в выборку, насколько результат устойчив и насколько тяжелый неблагоприятный хвост.

## Распределение

Вкладка **Распределение** показывает форму распределения той же combined-выборки, что используется в **Статистика** и **Raw data**.

Доступные виды графика:

- **Density** — сглаженная плотность распределения;
- **Box** — компактное представление медианы, квартилей и выбросов;
- **Violin** — сочетание плотности и boxplot, удобно для сравнения формы распределения.

Бизнес-интерпретация:

- узкое распределение означает более стабильный результат;
- широкое распределение означает высокий риск разброса;
- длинный левый хвост важен для downside risk;
- несколько пиков могут означать разные группы контрактов, сценариев или market regimes внутри одной выборки;
- если распределение смещено относительно нуля, это показывает общий bias выбранного portfolio slice.

**Распределение** отвечает на вопрос не только “сколько в среднем”, но и “какая форма неопределенности у результата”.

## Коротко

**Помесячно** показывает риск и разброс отдельного месяца сам по себе: сколько денег пришло или ушло именно в этом месяце.

**Liquidity-at-Risk** показывает риск накопленной кассовой позиции к каждому месяцу: хватает ли денег после учета всех предыдущих месяцев и текущего месяца вместе.

| Вкладка | Что считается | Бизнес-вопрос |
|---|---|---|
| Помесячно | Чистый денежный поток за конкретный месяц | В каком месяце притоки или оттоки наиболее волатильны? |
| Liquidity-at-Risk | Накопленная денежная позиция от начала периода до конкретного месяца | В каком месяце может возникнуть кассовый разрыв и насколько глубоким он может быть? |

## Помесячно

На вкладке **Помесячно** каждый месяц рассматривается изолированно от остальных месяцев.

Для каждого сценария Monte Carlo берется денежный поток конкретного месяца:

```text
monthly_net_cash_flow(month M) = inflows(M) - outflows(M)
```

Затем по всем сценариям строится распределение этого месячного значения: медиана, диапазон, P10, P90 и boxplot.

Пример интерпретации:

- январь: возможен отток;
- февраль: возможен приток;
- март: большой разброс;
- апрель: стабильный небольшой приток.

**Помесячно** не отвечает напрямую на вопрос, хватает ли денег на горизонте. Оно показывает, где именно месячные потоки наиболее неопределенны или рискованны.

Этот режим полезен для:

- анализа волатильности cash flow по месяцам;
- поиска месяцев с большим разбросом притоков и оттоков;
- понимания, какие периоды дают основной вклад в неопределенность;
- сравнения отдельных месяцев между собой.

## Liquidity-at-Risk

На вкладке **Liquidity-at-Risk** месяцы не рассматриваются изолированно. Для каждого сценария Monte Carlo строится накопленная траектория денежной позиции.

Для каждого сценария:

```text
cumulative_cash_position(Jan) = cash_flow(Jan)
cumulative_cash_position(Feb) = cash_flow(Jan) + cash_flow(Feb)
cumulative_cash_position(Mar) = cash_flow(Jan) + cash_flow(Feb) + cash_flow(Mar)
```

То есть значение в марте уже включает январь, февраль и март. Это не просто поток месяца, а состояние ликвидности к концу месяца.

Если линия или нижние перцентили уходят ниже нуля, это означает потенциальный кассовый разрыв. Поэтому zero-line на графике является границей дефицита ликвидности.

Этот режим полезен для:

- оценки вероятности дефицита денежных средств;
- определения месяца, где риск кассового разрыва максимален;
- оценки размера потенциального funding gap;
- планирования резервов ликвидности;
- ответа на вопрос, какой запас денег нужен, чтобы покрыть неблагоприятные сценарии.

## Почему результаты могут выглядеть по-разному

Один и тот же месяц может выглядеть безопасным в **Помесячно**, но рискованным в **Liquidity-at-Risk**.

Причина: **Помесячно** смотрит только на поток данного месяца, а **Liquidity-at-Risk** учитывает накопленный эффект предыдущих месяцев.

Пример:

| Месяц | Месячный поток | Накопленная позиция |
|---|---:|---:|
| Январь | -100 | -100 |
| Февраль | +20 | -80 |
| Март | +30 | -50 |

В **Помесячно** февраль и март выглядят положительными: там есть приток. Но в **Liquidity-at-Risk** позиция все еще отрицательная, потому что январский дефицит не был полностью покрыт.

Обратный пример:

| Месяц | Месячный поток | Накопленная позиция |
|---|---:|---:|
| Январь | +200 | +200 |
| Февраль | -80 | +120 |
| Март | -50 | +70 |

В **Помесячно** февраль и март выглядят как оттоки. Но в **Liquidity-at-Risk** кассового разрыва нет, потому что ранее накопленный приток покрывает будущие оттоки.

## Как читать график

На обеих вкладках используются месяцы по оси X и выбранная величина по оси Y. На графике отображаются:

- факт для месяцев до даты наблюдения;
- прогноз как распределение по Monte Carlo сценариям для будущих месяцев;
- P10 и P90 как границы распределения;
- boxplot как форма разброса сценариев.

Но смысл Y отличается:

- в **Помесячно** Y — это поток месяца;
- в **Liquidity-at-Risk** Y — это накопленная позиция к месяцу.

Отрицательное значение в **Помесячно** означает месячный отток. Отрицательное значение в **Liquidity-at-Risk** означает потенциальный накопленный дефицит ликвидности.

## Raw data

Вкладка **Raw data** показывает sample values, из которых построены **Статистика** и **Распределение** для текущей combined-выборки.

Что важно:

- каждая строка — значение одного sample после backend-агрегации по текущим фильтрам;
- это не обязательно физическая строка parquet-файла `fact_simulation`;
- при выбранном периоде и scope filters backend сначала выбирает строки, затем агрегирует их до sample-level значения;
- если включен режим `prices`, значение sample является derived price: `sum(value) / sum(volume)`;
- выгрузка raw data через меню `...` используется для диагностики и сверки: в filter mode она отдаёт физические строки `fact_simulation`, а в Balance mode — точные derived значения таблицы с колонками `sample_index` и `value_rub`.

Эта вкладка нужна, когда необходимо:

- проверить, какие значения реально попали в расчет распределения;
- увидеть outliers;
- сравнить frontend-график с внешним анализом;
- выгрузить данные для ручной проверки или отчета.

Важно не смешивать **Raw data** и **Liquidity-at-Risk**: Raw data показывает sample values текущей combined-выборки, а Liquidity-at-Risk строит path-dependent cumulative view по месяцам.

## Итог

**Помесячно** — анализ распределения денежных потоков по отдельным месяцам. Он показывает, где сами месячные притоки и оттоки наиболее рискованные.

**Liquidity-at-Risk** — анализ распределения накопленной денежной позиции по месяцам. Он показывает, когда и с какой величиной может возникнуть кассовый разрыв с учетом всей предшествующей траектории cash flow.

Если нужно понять, какой месяц дает самый нестабильный cash flow — используйте **Помесячно**.

Если нужно понять, хватит ли денег и какой резерв ликвидности нужен — используйте **Liquidity-at-Risk**.

Для корректной интерпретации всех вкладок см. [Верхние фильтры анализа](help:valuation-analysis-filters).
