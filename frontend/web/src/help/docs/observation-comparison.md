# Observation Date Comparison

Этот документ описывает экран `/dashboard/observation-comparison`.

Описание верхних фильтров вынесено в отдельную справку: [Верхние фильтры анализа](help:valuation-analysis-filters).

## Назначение

**Observation Date Comparison** сравнивает распределения simulation results между несколькими датами наблюдения.

Экран отвечает на вопрос: как изменилась форма риска, медиана и рыночный фон между разными `observation_date` при одинаковой области анализа.

## Что такое observation date

`Observation date` — дата наблюдения или partition simulation run. Для разных дат могут отличаться:

- рыночные входы;
- доступные curve values;
- набор сценариев;
- valuation type;
- состояние портфеля или сохраненного balance tree;
- распределение итогового результата.

Поэтому сравнение по датам — это не просто временной график одной метрики. Это сравнение нескольких распределений, каждое из которых рассчитано на своей дате наблюдения.

## Верхний блок фильтров

Верхний блок выбирает область анализа, одинаковую для всех сравниваемых дат:

- источник: **По симуляциям** или **По балансу**;
- основной `Observation date`;
- `Scenario` и `Valuation type`;
- период анализа;
- режим периода: `Valuations`, `Payments` или `Prices`;
- currency/target;
- scope filters: markets, products, GL accounts и другие доступные фильтры.

Подробно см. [Верхние фильтры анализа](help:valuation-analysis-filters).

## Основная и дополнительные даты

На экране есть две группы дат:

- основная дата в стандартном верхнем контроле `Observation date`;
- дополнительные даты в поле **Доп. даты для сравнения**.

Фактический набор сравнения строится как объединение:

```text
effective_observation_dates = primary_observation_date ∪ additional_observation_dates
```

Даты дедублицируются и сортируются. Поэтому если основная дата также выбрана в дополнительных датах, она будет показана один раз.

## Режим “По симуляциям”

В режиме **По симуляциям** backend для каждой выбранной даты читает simulation rows и применяет одинаковые filters:

- period from / period to;
- period mode;
- target;
- markets;
- products;
- GL accounts;
- scenario, если выбран.

Результат — отдельная sample distribution для каждой observation date.

Этот режим полезен, когда нужно понять, как меняется риск конкретного portfolio slice между датами наблюдения.

## Режим “По балансу”

В режиме **По балансу** backend сравнивает balance-derived results по сохранённым balance tree metadata в partition каждой выбранной `observation_date`.

Особенности:

- selector GL Balance tree на этом экране недоступен: для разных `observation_date` может быть применено разное сохранённое дерево;
- для каждой даты backend независимо читает saved metadata balance layer и берёт последнее сохранённое дерево в data partition;
- target принудительно соответствует balance semantics;
- period mode трактуется как balance/payments-based view;
- scenario, если выбран, применяется к modelled simulation component.

После выполнения сравнения верхний информационный блок показывает applied trees per date: `observation_date`, `balance_tree_slug`, имя дерева, `valuation_year` и `saved_at`.

Если для выбранной даты нет saved metadata balance layer, сравнение в режиме **По балансу** не может определить корректное дерево автоматически и backend вернёт ошибку. В этом случае нужно сначала сохранить баланс для соответствующей даты на Balance screen.

Этот режим полезен, когда нужно сравнивать не raw simulation slice, а бизнес-структуру баланса между датами наблюдения с учётом фактически сохранённой версии дерева для каждой даты.

## Верхняя панель графика

Верхняя панель графика показывает распределение результата по каждой observation date.

Для каждой даты строится violin distribution:

- ширина violin показывает плотность sample values;
- вертикальная ось показывает выбранную величину: value или price;
- линия медианы соединяет центральные значения по датам;
- подписи медианы помогают быстро увидеть сдвиг центрального сценария.

Как читать:

- если violin сдвигается вверх — выбранная величина выросла;
- если violin становится шире — неопределенность увеличилась;
- если нижний хвост стал длиннее — downside risk усилился;
- если медиана изменилась без расширения violin — изменился центр распределения, но не обязательно риск разброса;
- если форма violin изменилась, изменился профиль сценариев, а не только средний уровень.

## Нижняя панель факторов

Нижняя панель показывает динамику рыночных факторов между теми же observation dates.

Доступные переключатели:

- Brent;
- TTF;
- USD/RUB.

Факторы нормируются относительно первой доступной даты: первое значение принимается за `100%`, следующие точки показывают относительное изменение.

Это позволяет сравнивать факторы с разными единицами измерения на одной оси.

## Зачем нужна нижняя панель

Нижняя панель помогает объяснить, почему изменилось распределение в верхней панели.

Примеры интерпретации:

- вырос Brent, и распределение P&L сместилось вверх — portfolio slice чувствителен к Brent положительно;
- вырос USD/RUB, а распределение в RUB резко изменилось — результат чувствителен к валютному фактору;
- факторы почти не менялись, но violin сильно изменился — причина может быть в портфеле, scenario composition, curve availability или фильтрах;
- фактор изменился, но распределение почти не изменилось — выбранный slice слабо чувствителен к этому фактору.

## Когда использовать

Используйте **Observation Date Comparison**, если нужно:

- сравнить риск между несколькими датами наблюдения;
- понять, как изменилась медиана distribution;
- увидеть, стала ли выборка более рискованной или более стабильной;
- связать изменение distribution с Brent, TTF или USD/RUB;
- сравнить текущую дату наблюдения с предыдущими расчетами;
- проверить, не вызван ли скачок результата изменением рынка или входных данных.

## Отличие от других экранов

| Экран | Что сравнивает | Главный вопрос |
|---|---|---|
| Simulation Analysis | Одну выбранную observation date и разные представления результата | Как выглядит риск на текущей дате? |
| Scenario Analysis | Baseline и shocked scenarios | Как изменится риск при факторных шоках? |
| Observation Date Comparison | Несколько observation dates | Как риск изменился между датами наблюдения? |

## Практический порядок работы

1. Выберите источник: **По симуляциям** или **По балансу**.
2. Выберите основную `Observation date`.
3. Выберите дополнительные даты для сравнения.
4. Задайте period, mode, target и scope filters.
5. Включите нужные факторы нижней панели.
6. Нажмите **Сравнить**.
7. Сначала сравните медианы и форму violin distributions.
8. Затем сопоставьте изменения с нижней панелью факторов.
